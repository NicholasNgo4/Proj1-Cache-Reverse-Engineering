# scripts/

Processing and plotting scripts. Keep one row per script in the table below, updated
as scripts are added.

| Script | Input (raw/processed data) | Output (plot/table) | Notes |
|---|---|---|---|
| `run_capacity_sweep.sh <machine> [core] [args...]` | none (builds + runs `cache_bench --experiment capacity`) | `data_raw/<machine>/capacity/capacity_<timestamp>.csv` | Pins with `taskset`; use `srun --cpu-bind=cores` directly on Hazel instead. One manual sweep -- use `run_capacity_full.sh` for the whole per-machine pipeline. |
| `run_capacity_full.sh <machine> <core> [coarse_max_bytes]` | none (builds + runs the full capacity pipeline) | raw (`.csv.gz`) + processed CSVs under `data_raw/<machine>/capacity/` and `data_processed/<machine>/capacity/`, plots under `data_processed/<machine>/capacity/plots/`, full transcript log next to the raw CSVs | **One-command per-machine capacity pipeline**, built after doing this by hand on Sunbird: coarse sweep -> auto boundary detection (`detect_cache_hierarchy.py --machine-readable`) -> dense sweep bracketing each boundary (+-3 octaves) -> 2 reproducibility repeats on the deepest boundary's window (that's the one that turned out ambiguous on Sunbird) -> a fixed 4x tail-extension sweep past the coarse ceiling to check for a further plateau (memory-safety clamped to 25% of available RAM) -> calls `plot_capacity.py` automatically with the detected boundaries -> gzips its own raw CSVs (~9x smaller; see `.gitignore` -- commit the `.csv.gz`, not a decompressed copy). Deliberately non-adaptive (no "did it plateau, extend again?" loop) so it doesn't need per-machine debugging; if a machine's result still looks unresolved after this, do one targeted manual follow-up sweep for that machine rather than extending this script's logic (gzip any ad hoc raw CSVs from that follow-up by hand before committing). Prints the run's core/seed/timestamp/detected-boundaries at the end -- copy those into that machine's `data_raw/<machine>/README.md` manually (this script does not write the README itself).|
| `summarize_raw.py <raw.csv> -o <out.csv>` | `data_raw/<machine>/<experiment>/*.csv` | `data_processed/<machine>/<experiment>/summary.csv` | Generic: groups raw per-batch rows by every column except the trailing (trial-index, value) pair and computes n/mean/median/stddev/min/q1/q3/p5/p95/max/n_outliers. |
| `detect_cache_hierarchy.py <summary.csv> [--machine-readable]` | `data_processed/<machine>/capacity/summary.csv` | printed level table + capacity-boundary hypotheses; `--machine-readable` instead prints just the boundary byte values, one per line, for scripts to consume | Timing-only knee detection on the median-latency-vs-size curve; a starting hypothesis to confirm against box plots, not the final report number. Used internally by `run_capacity_full.sh`. |
| `plot_capacity.py <summary.csv...> -o <dir> [--machine NAME] [--boundary SIZE]...` | one or more `data_processed/<machine>/capacity/*summary.csv` (coarse + any dense zoom windows + independent repeat runs; rows tagged by the `pattern` column) | `<dir>/capacity_curve.{pdf,png}` (median latency vs. size, random vs. sequential overlay), `<dir>/capacity_boxplots.{pdf,png}` (box-and-whisker at points immediately below/at/above each `--boundary`, drawn from the summary's own percentile columns) | Vector PDF + PNG preview. No grid lines, black/grayscale, per the required figure style. Box plots use p5/p95 as whiskers since raw per-batch data isn't re-read. When the same (pattern, size) point appears in more than one input file (overlapping sweeps or a deliberate repeat run), `combine_duplicate_rows()` averages the medians, widens the whisker to the union of the inputs' p5/p95, and the box-plot annotation reports `n_outliers`, the number of independent runs combined, and their run-to-run median spread as a percentage -- so a point with, e.g., "5 runs, 95% spread" is visibly flagging itself as unreliable rather than looking as clean as a "1,000 samples" single-run point. |
| `run_associativity_full.sh <machine> <core> [cache_bytes_csv]` | none (builds + runs the full associativity pipeline); `cache_bytes_csv` is an optional comma-separated list of per-level capacities (bytes), one associativity sweep per value | raw (`.csv.gz`) + processed CSVs under `data_raw/<machine>/associativity/<level>/` and `data_processed/<machine>/associativity/<level>/`, plots under `data_processed/<machine>/associativity/<level>/plots/`, full transcript log next to the raw CSVs | **One-command per-machine, per-level associativity pipeline**: for each cache level, sweeps `num_ways_probed` = 2..64 (both patterns) at a node-to-node stride fixed to that level's own capacity -- see `main_code/common/associativity.h` for why that stride guarantees every probed node lands in the same cache set regardless of the (separately measured) line size -- then `detect_associativity.py` locates the hit->thrashing knee, then 2 reproducibility repeats, then `plot_associativity.py`. If `cache_bytes_csv` is omitted, capacities are auto-detected from an existing capacity run and rounded to the nearest power of two, but this prints a loud warning: `detect_cache_hierarchy.py`'s coarse first-pass boundary is a known-unreliable heuristic for L1 specifically (confirmed off by ~9x on Sunbird -- see `data_raw/sunbird/README.md`), so an explicit override built from that machine's own hand-confirmed capacity boundaries is strongly preferred. Deliberately non-adaptive, same philosophy as `run_capacity_full.sh`/`run_line_size_full.sh`. Prints the run's core/seed/timestamp/cache_bytes/detected-associativity per level at the end -- copy those into that machine's `data_raw/<machine>/README.md` manually. |
| `detect_associativity.py <summary.csv> [--machine-readable]` | `data_processed/<machine>/associativity/<level>/base_random_summary.csv` (single cache level / cache_bytes stride) | printed hit/thrashing segment table + associativity estimate; `--machine-readable` instead prints just the estimated way-count, for scripts to consume | Timing-only knee detection on the median-latency-vs-num_ways curve (same rolling-baseline algorithm as `detect_cache_hierarchy.py`, but expects exactly one knee since each run targets one cache level's own set). A starting hypothesis to confirm against box plots, not the final report number. Used internally by `run_associativity_full.sh`. |
| `plot_associativity.py <summary.csv...> -o <dir> [--machine NAME] [--level NAME] [--estimate N]` | one or more `data_processed/<machine>/associativity/<level>/*summary.csv` (base sweep + independent repeat runs; rows tagged by the `pattern` column) | `<dir>/associativity_curve.{pdf,png}` (median latency vs. num_ways_probed, random vs. sequential overlay, with a marker at `--estimate`), `<dir>/associativity_boxplots.{pdf,png}` (box-and-whisker at num_ways immediately below/at/above `--estimate`) | Vector PDF + PNG preview, same black/grayscale/no-gridline style as `plot_capacity.py`/`plot_line_size.py`. Overlapping (pattern, num_ways) rows across input files are combined the same way (`combine_duplicate_rows()`: average medians, union the p5/p95 whiskers, annotate run count + spread). |
| `run_associativity_stride_scan.sh <machine> <core> <capacity_bytes> [A_guess_csv]` | none (builds + runs an EXPLORATORY diagnostic scan) | `data_raw/<machine>/associativity/stride_scan/<ts>/*.csv.gz`, `data_processed/<machine>/associativity/stride_scan/<ts>/comparison.csv` (the diagnostic table: `a_guess,stride_bytes,pages_in_arena,detected_ways`), transcript log | **New (2026-09-12), NOT a final-result pipeline** -- diagnostic for the large-stride DTLB/page confound documented in CLAUDE.md's associativity section. Instead of `run_associativity_full.sh`'s fixed stride = full target capacity (one probed node per page for any capacity above 4 KiB), tries `stride = capacity_bytes / A_guess` for a list of candidate divisors: any `A_guess` that evenly divides the true associativity still yields a mathematically valid same-cache-set stride (see the script's header comment), but touches far fewer distinct pages for the same `num_ways` swept. If the same knee recurs across multiple different `A_guess` (hence different page counts), that's evidence of a real signal rather than a page-count artifact; a knee unique to one `A_guess` is not trustworthy. Reduced sample count (200,000 vs. the standard 1,000,000), random pattern only, no repeats -- fast enough to try many candidates; a self-consistent candidate found here must still be confirmed with `run_associativity_full.sh`-equivalent full rigor before citing a number. Validated on Upgrade against the known L1=8-way result (recovered exactly, self-consistent across a 200-1,600 page range) -- see `data_raw/upgrade/README.md`'s associativity/ section for the full writeup, including an L2/LLC-scale attempt that found a promising but NOT yet citable two-tier staircase result. |
| `run_line_size.sh <machine> <core> <boundaries_csv>` | none (builds + runs the full line-size pipeline) | raw (`.csv.gz`) + processed CSVs under `data_raw/processed/<machine>/line_size/level_<bytes>/`, plots | One pipeline per cache-level boundary passed in (from that machine's own capacity results): runs BOTH the family-of-curves method (PROJECT 1.pdf Fig. 3 / "Example B", all 5 steps, offset-validated) and the single-curve ramp-saturation method, then reports whether the two independently-designed methods agree. |
| `detect_line_size.py <summary.csv> [--machine-readable]` | processed single-curve line_size summary | printed line-size estimate | Corrects for the footprint/boundary multiplier when inferring line size from a single continuous stride sweep. |
| `plot_line_size.py <summary.csv...> -o <dir>` | processed single-curve line_size summaries | `line_size_curve`/`line_size_boxplots` | Curve + box-plot figures for the single-curve ramp-saturation method. |
| `plot_line_size_family.py <summary.csv...> -o <dir>` | processed family-of-curves line_size summaries | family curve overlay + boxplots | Overlays one curve per candidate stride; infers the smallest stride whose elbow separates from the shared baseline. |
| `plot_line_size_offset.py <summary.csv> -o <dir>` | processed step-4 (node-0 offset) summary | offset elbow plot | The step-4 cross-alignment confirmation for one candidate stride (tests offsets just below/at/above the candidate). |
| `run_capacity_validate.sh <machine> <core> <boundaries>` | none (builds + runs a targeted discrete-size sweep) | raw/processed CSVs under `data_raw/processed/<machine>/capacity_validate/` | Complements `run_capacity_full.sh`'s log-spaced auto-detection sweep with 4 fixed discrete size groups (L1D/L2/L3/DRAM) densely sampled right at each already-hypothesized boundary, to resolve cases where the coarse grid straddled a real edge without landing close enough to it. |
| `analyze_capacity_validate.py <summary.csv>` | processed `capacity_validate` summary | printed plateau/ramp/step classification per point | Classifies each tested size as a flat plateau, a monotonic transition ramp, or a step using only the already-computed percentile columns -- no hardware topology lookup. |
| `plot_capacity_validate.py <summary.csv...> -o <dir>` | processed `capacity_validate` summaries | `capacity_validate` curve/boxplots | Reuses `plot_capacity.py`'s box-plot code, but plots each of the 4 discrete size groups as its own disconnected line segment (not one continuous curve) since there are deliberate large gaps between groups. |
| `plot_capacity_zoom.py <summary.csv> -o <dir>` | processed `capacity/summary.csv` | `capacity_zoom_{L1,L2,L3_LLC}.{pdf,png}` | Re-plots the same capacity summary data (no new sweeps) three times, each zoomed to an octave window centered on one level's own boundary, for Section 5's per-machine subsections. |
| `run_hit_latency_full.sh <machine> <core> <level>:<footprint_bytes>[,...]` | none (builds + runs the full hit-latency pipeline) | raw/processed CSVs under `data_raw/processed/<machine>/latency/hit/<level>/`, plots | One-command per-level hit-latency pipeline: base sweep (dependent + independent load modes, both patterns) at a single fixed footprint -> reproducibility repeats -> plots. Not adaptive -- one fixed footprint per level, no auto-detection. |
| `plot_hit_latency.py <summary.csv...> -o <dir>` | processed hit_latency summary (one footprint/level) | `hit_latency_boxplots` | One box per (load_mode, pattern) combination at the single fixed footprint; flags `[UNEXPECTED]` when independent load isn't faster than dependent. |
| `run_miss_latency_full.sh <machine> <core> <transition>:<target_bytes>:<evict_bytes>` | none (builds + runs the full miss-latency pipeline) | raw/processed CSVs under `data_raw/processed/<machine>/latency/miss/<transition>/`, plots | Base sweep (both eviction-set traversal patterns) -> reproducibility repeats -> plots for one source->destination cache-level transition; `target_bytes`/`evict_bytes` must both be hand-confirmed capacity boundaries. |
| `plot_miss_latency.py <summary.csv...> -o <dir> [--hit-latency-summary <csv>]` | processed miss_latency summary, optionally a paired hit_latency summary | `miss_latency_boxplots`, annotated with the incremental miss penalty when the hit-latency summary is given | One box per traversal pattern. |
| `run_inclusion_policy_full.sh <machine> <core> <pairing>:<upper_bytes>:<lower_bytes>:<transition>[,...]` | none (builds + runs the full inclusion/exclusion pipeline) | raw/processed CSVs under `data_raw/processed/<machine>/inclusion_policy/<pairing>/`, plots | Per (upper level, lower level) pairing: single-shot "survived" calibration -> main eviction sweep (both patterns, base + 2 repeats) -> classification against this machine's own calibration -> plots. See `main_code/common/inclusion_policy.h` for the method rationale and known limitations. |
| `classify_inclusion_policy.py <raw.csv>` | RAW (not summarized) `--experiment inclusion_policy` output | printed survived-like/invalidated-like/ambiguous percentages | Compares each trial's reload latency against two calibration classes already measured on this machine (that level's own hit_latency "survived" class and the deeper level's "invalidated" class) -- never reads hardware topology. |
| `plot_inclusion_policy.py <summary.csv...> -o <dir>` | processed inclusion_policy summary | `inclusion_policy_boxplots` | One box per (channel, pattern) -- target/control x random/sequential -- with horizontal reference lines at the calibrated survived/invalidated hit-latency classes. |
| `run_pmu_verification.sh <machine> <core> <level>:<footprint_bytes>[,...]` | none (Phase II only -- requires the `phase1-timing-only` tag first) | raw perf/cache_bench CSVs + `pmu_summary_<ts>.csv` under `data_raw/processed/<machine>/pmu/<level>/` | Wraps the same `hit_latency` `cache_bench` invocation already used in Phase I in `perf stat`, split into 4 separate 2-event groups (cache/L1/LLC/cycles), for an independent hardware-counter cross-check of Phase I's ticks/access and boundary placement. | `summarize_pmu.py <raw dir> -o <out.csv>` | raw `perf stat -x,` CSVs + `cache_bench`'s own CSV from `run_pmu_verification.sh` | `pmu_summary_<ts>.csv` | Parses the 4 perf-stat groups into one combined row per run_tag plus a median-of-repeats row; tolerates `<not counted>`/`<not supported>` events gracefully. |

**Historical, not part of the final pipeline:** `cache_bench.c`, `pointer_chase.h`,
`timer_x86.h`, and `timer_arm.h` in this directory are all from the very first commit's
single-mode, capacity-only skeleton (median only, no distribution stats, no line-size/
associativity/latency/inclusion/hit-rate experiments) — superseded entirely by
`main_code/common/`, `main_code/x86_64/`, `main_code/aarch64/`, and
`main_code/software_hit_rate/`, which is what `Makefile` actually builds and what every
script above runs (confirmed byte-for-byte different from their `main_code/` counterparts,
not stale copies of the same file). Nothing in this repository builds or calls these four
files anymore; kept for history rather than deleted, but **do not use them as the "final
main reverse-engineering source code" the assignment requires** — that is `main_code/`
only. Consider deleting them from a future commit if they risk confusing a grader.
